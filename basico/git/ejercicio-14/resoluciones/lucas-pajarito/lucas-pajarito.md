# Flujo de Trabajo con Rama Personal y Pull Request

## Objetivo

Aplicar un flujo de trabajo utilizando Git y GitHub mediante la creación de una rama personal, el registro de una solución, el envío de los cambios al repositorio remoto y la elaboración de una Pull Request (PR) con la información necesaria para su revisión.

---

## Descripción del trabajo realizado

Durante el desarrollo del ejercicio se siguieron los pasos necesarios para integrar una nueva solución al proyecto sin afectar la rama principal.

Las actividades realizadas fueron las siguientes:

1. Se creó una **rama personal** a partir de la rama principal para trabajar de forma independiente.
2. Se agregó la solución del ejercicio dentro de la carpeta **`resoluciones`**.
3. Se verificaron los cambios realizados antes de registrarlos en Git.
4. Se creó un **commit** con un mensaje descriptivo que identifica claramente la modificación realizada.
5. Se realizó el **push** de la rama al repositorio remoto en GitHub.
6. Finalmente, se preparó una **Pull Request (PR)** para solicitar la integración de los cambios al proyecto principal.

---

## Descripción de la Pull Request

La Pull Request fue redactada incluyendo la información necesaria para facilitar su revisión.

### Objetivo

Incorporar la solución desarrollada en la carpeta `resoluciones` utilizando una rama independiente, manteniendo organizado el flujo de trabajo del proyecto.

### Cambios realizados

- Creación de una rama personal.
- Implementación de la solución solicitada.
- Incorporación del archivo correspondiente en la carpeta `resoluciones`.
- Registro de los cambios mediante un commit.
- Publicación de la rama en el repositorio remoto.

### Validación

Antes de crear la Pull Request se verificó que:

- La solución funcionara correctamente.
- Los archivos modificados fueran únicamente los necesarios.
- El proyecto no presentara conflictos con la rama principal.
- El historial de commits reflejara claramente los cambios realizados.

---

## Resultado obtenido

Al finalizar el proceso se obtuvo:

- Una rama personal con los cambios desarrollados.
- La solución almacenada correctamente en la carpeta `resoluciones`.
- Los cambios registrados mediante un commit.
- La rama publicada en GitHub mediante un push.
- Una Pull Request lista para ser revisada e integrada al proyecto principal.

---

## Conclusión

Este ejercicio permitió poner en práctica un flujo de trabajo colaborativo utilizando Git y GitHub. La creación de ramas personales, el uso de commits descriptivos, el envío de cambios al repositorio remoto y la elaboración de Pull Requests facilitan la organización del proyecto, mejoran la colaboración entre desarrolladores y permiten revisar las modificaciones antes de integrarlas a la rama principal.
